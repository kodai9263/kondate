# スマホアプリ技術検証

仕様書は`docs/mobile-app-spec-2026-09-22.md`。iPhone実機で献立・買い物・通知まで確認済み。Android実機、退会、アプリ内課金、ストア申請は未完了。

## 起動

1. `npm ci`
2. `.env.example`を参考に`.env.local`へ公開可能なSupabase URLとpublishable／anonキーを設定する。秘密鍵は入力しない。
3. リポジトリ側でNext.jsの開発サーバーを3000番に起動する。
4. このディレクトリで`npm run dev`を実行する。開発画面の`/api`は3000番のNext.jsへ転送される。

端末向けのビルドは、`VITE_API_BASE_URL`に本番または検証用のHTTPSアプリURLを設定して`npm run build`する。その後`npm run cap:sync`で同梱資材を更新する。`VITE_API_BASE_URL`が未設定またはHTTPS以外ならビルドを止める。開発用のVite URLを端末向けビルドに埋め込まない。

## 2026-09-29 本番API・端末保存・通知の検証

- スマホ用の認証付きAPIを本番サイトへ反映。未認証のGETは401、iPhone／Androidの送信元を付けたOPTIONSは204で応答することを確認した。
- iPhone SEの更新版で本人がログインし、献立と買い物リストを表示した。買い物リストの一時追加→再取得→削除→再取得では件数が元に戻った。
- ログイン情報はiOS Keychain／Androidの安全な保存領域へ保存する。iPhoneでアプリを完全終了して開き直し、パスワードを再入力せず献立が表示された。
- 買い物リストはユーザーID・家族ID・取得日時と共に端末の安全な保存領域へ保存する。iPhoneでオンライン表示後に機内モードとWi-Fi OFFにし、アプリを完全終了して再起動しても、取得時刻付きのリストを読み取り専用で表示できた。通信復帰後は最新のリストを取得し、編集できることを確認した。端末時計に基づく24時間の期限を設けたが、時計操作への完全な耐性は未実装。共有解除も圏外端末に即時反映されないため、ストア公開前に権限期限の扱いを再設計する。
- 通知は初期値OFFで、買い物と仕込みの曜日・時刻を端末ごとに設定できる。iOS／Androidともプラグインを含むビルドは成功した。端末での通知受信、時刻変更やタイムゾーン変更の検証は未実施。
- AndroidはデバッグAPKのビルドまで。Android実機のインストール、ログイン、圏外閲覧、通知は未確認。
- Apple／Googleの有料開発者登録、アプリ内課金、退会導線、ストア申請は未実施。実際の配布準備には別途実装と審査が必要。
