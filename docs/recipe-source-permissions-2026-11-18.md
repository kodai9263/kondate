## 実装

最新 main の a6a8eac を元に、`codex/recipe-source-permissions` の独立した作業コピーで実装。
作業コピー: `/private/tmp/kondate-source-permissions-20261117`。
元の作業フォルダの大量の未コミット変更は変更していない。

- Webのメニュー一覧から調理時間の表示・絞り込みを除去。献立生成の時間条件は維持。
- メニュー一覧と詳細に、提供元・作者／チャンネル・元URLを表示。YouTubeは任意の開始秒を指定可能。
- `/admin/recipe-sources` に提供元・作者別の一覧、検索、承諾状況フィルター、依頼用の料理名／URLコピー、編集フォーム。
- 対象はアプリ提供メニューと管理者本人の家庭のメニュー。非表示・アーカイブ済みも管理一覧で区別して表示。他の家庭の料理は管理用取得の対象外。
- 記録のない承諾状況は「未確認」。承諾済みには許可範囲・確認日・承諾記録を必須化。
- URL取り込み休止と本文の表示保留は維持。承諾記録の保存で公開状態を切り替えない。
- 今回の対象はWeb。iOSネイティブ画面は未変更。

## 権限と保存

`recipe_permission_owner` は一人だけ登録可能。未設定は全員拒否し、一般ユーザーは自己昇格できない。
サーバー側のページ／保存Actionが `auth.getUser()` とDBの管理者行を確認する。

`recipe_sources` は公開可能な出典だけを保持し、一般ユーザーは閲覧可能なレシピの出典のみ読める。
`recipe_source_permissions` はRLSで管理者だけが取得・挿入・更新可能。同じ家庭のメンバーも不可。
`save_recipe_source_permission` は SECURITY INVOKER。出典と承諾記録を一つのトランザクションで保存する。

非表示のメニューも一覧にする管理用サーバー取得のみ既存service-roleクライアントを使用する。
管理者確認後、公開メニューと本人の家庭に取得条件を固定し、料理名と必要な出典項目のみ読む。
一般画面やブラウザにはservice-roleキーを渡さない。
