対象はiOSアプリ「きょうのごはん｜献立・買い物リスト」（Apple ID `6826687098`）の初回公開。2026年11月1日のApp Store Connect確認では「1.0 提出準備中」で、審査には未提出。メールは既存の `kyounogohan2@gmail.com` を継続利用し、確認メールの差出人にも使用する方針を所有者が確認済み。送信接続はGoogleの本人確認・専用パスワードの入力待ち。退会の一般受付は、別途承認するまで無効を維持する。

## 審査担当者向けメモの準備

審査用アカウントを作成・検証してから、以下の経路をメモへ記入する。一般受付が停止中の機能を「利用可能」と記載しない。

1. メールアドレスとパスワードでログイン。「今日」で献立と調理手順を確認。
2. 「献立」で料理の変更・作らない日の指定。「メニュー」で自作料理の登録・編集・非表示削除。
3. 「買い物」でリストの追加・チェック・削除と再読み込み。
4. 「設定」の家族プランから月額・年額購入、購入の復元、Appleの契約管理へ移動。
5. 通知は「設定」で曜日・時刻を保存し、端末の通知許可を得て確認。
6. 退会は「設定」から、削除対象と定期購入の別途解約を確認して実施できる状態にして提出。

退会を試すとその審査用アカウントは使用できなくなる。審査時に再度ログインできるよう、削除確認用と通常の機能確認用を分ける準備が必要。

## データ申告の照合案

Web版の解析とiPhoneアプリ内のデータ収集を混同しない。Appleの定義に沿って、アプリと組み込んだサービスが収集する情報を確認する。

| 確認するデータ | 実装上の用途 | 申告前の確認 |
| --- | --- | --- |
| 表示名・メールアドレス | 登録、ログイン、家族の識別 | 連絡先情報・ユーザーに関連付け・アプリの機能 |
| アカウントID・家族ID | 認証、家族単位のアクセス管理 | ユーザーID・ユーザーに関連付け・アプリの機能 |
| 商品・取引ID、契約状態、有効期限 | 購入・復元の検証、利用権限 | 購入履歴・ユーザーに関連付け・アプリの機能 |
| 献立・買い物・自作料理・チェック履歴 | ユーザーが登録し家族で共有する内容 | その他のユーザーコンテンツ等の区分を質問票と照合 |
| 写真・アレルギー・フィードバック | Web版側にも登録経路がある | iOSから実際に送信する範囲を確認し、Webの機能だけから決めない |
| 通信・エラーの記録 | Vercel、Supabase等の運用 | 保存範囲とユーザーへの関連付けを確認 |

今回確認したスマホ用コードにはGoogle Analytics等の広告追跡SDKは見つかっていない。トラッキングの回答は外部サービスを含む最終確認後に確定する。

参考：[AppleのAppプライバシー詳細](https://developer.apple.com/app-store/app-privacy-details/)。
