# きょうのごはん App Store初回申請の準備

対象はiOSアプリ「きょうのごはん｜献立・買い物リスト」（Apple ID `6826687098`）の初回公開。2026年11月1日のApp Store Connect確認では「1.0 提出準備中」で、審査には未提出。専用GmailはGoogleの本人確認待ちのため切り替えない。退会の一般受付も、別途承認するまで無効を維持する。

## 申請前に完了する項目

| 項目 | 現在の状態 | 次の操作 |
| --- | --- | --- |
| 説明文・キーワード | Appleに登録済み。購入の説明は未記載 | 下記の購入説明を加え、内容確認後に保存 |

| プライバシーポリシーURL・データ申告 | Appleでは未登録 | 修正版 `/privacy` の本番確認と、アプリのデータ経路の最終照合後に登録 |
| カテゴリ・サブタイトル | Appleでは未設定 | フード／ドリンク、下記サブタイトルを候補とする |
| 年齢制限指定・コンテンツ配信権 | Appleでは未設定 | 料理の出典・共有範囲を含めて回答を確認。権利を推定して申告しない |
| スクリーンショット | 表示したiPhone中型の枠は0枚 | 必須サイズのiPhone・iPad画像を確認して用意。実ユーザーのメール・家族情報は掲載しない |

| 家族プラン | 月額・年額の2商品を登録済み、どちらも提出準備中。月額の審査用画像・メモは空欄 | 初回アプリと一緒に提出できるよう商品側の不足項目も確認 |
| 審査用アカウント・連絡先 | Appleのバージョン画面では空欄 | 専用アカウントの用意と実ログイン確認。パスワードはこの資料やGitに記録しない |
| リリース方法 | Appleでは承認後の自動公開 | 初回公開の方針に合わせ、手動公開へ変更する内容を確認 |
| 退会 | テスト専用アカウントの実機削除をユーザーが確認済み。一般受付は停止する指定あり | 残る共有写真等の確認と一般受付開始の承認を済ませてから審査提出 |

| ライブラリの安全更新 | 本番依存の監査で5件を検出 | 承認後に修正版へ更新し、テスト・監査・ビルドを再確認 |

App Store提出には必須情報とビルドの指定が必要。アカウントを作成できるアプリは、アプリ内から削除手続きを始められる必要があるため、一般受付を停止したまま審査完了とはしない。

参考：[Appleの申請手順](https://developer.apple.com/help/app-store-connect/manage-submissions-to-app-review/submit-an-app)、[アカウント削除の要件](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion)。

### プロモーション用テキスト

献立を決めて、買うものを確認。料理の変更や「作らない日」の設定、自分のメニューの保存も。家族の毎日のごはんを、ひとつのアプリで準備できます。

### 概要

「今日、何を作ろう？」を家族で考えやすく。
きょうのごはんは、献立と買い物リストをまとめて管理するアプリです。

■ 献立を確認・調整
週間・月間の献立を確認し、主菜や副菜を変更できます。外食などで作らない日も設定できます。

■ 買い物リストを家族で共有
献立に合わせた買い物リストを確認し、購入済みのチェックや買うものの追加ができます。通信できないときは、保存済みのリストを取得時刻付きで確認できます。通信できない間は編集できません。

■ わが家のメニューを保存
自分の料理の材料や作り方を登録・編集し、献立に選べます。

■ 家族の人数に合わせて
大人・子どもの人数を設定し、献立と買い物の分量計算に使えます。

■ 買い物・仕込みのお知らせ
曜日と時刻を設定して、この端末で通知を受け取れます。

■ 家族プラン
週間・月間の献立と買い物リストを継続利用でき、家族を招待して共有できます。
日本での料金は月額480円（1か月）または年額4,800円（1年間）です。最終的な価格はAppleの購入確認画面をご確認ください。

自動更新の定期購入です。支払いはApple Accountに請求されます。期間終了の24時間前までに解約しない限り更新されます。購入後の変更・解約はAppleのサブスクリプション管理から行えます。購入の復元はアプリの「設定」から行えます。

## 審査担当者向けメモの準備

審査用アカウントを作成・検証してから、以下の経路をメモへ記入する。一般受付が停止中の機能を「利用可能」と記載しない。

1. メールアドレスとパスワードでログイン。「今日」で献立と調理手順を確認。
2. 「献立」で料理の変更・作らない日の指定。「メニュー」で自作料理の登録・編集・非表示削除。
3. 「買い物」でリストの追加・チェック・削除と再読み込み。
4. 「設定」の家族プランから月額・年額購入、購入の復元、Appleの契約管理へ移動。
5. 通知は「設定」で曜日・時刻を保存し、端末の通知許可を得て確認。
6. 退会は「設定」から、削除対象と定期購入の別途解約を確認して実施できる状態にして提出。

退会を試すとその審査用アカウントは使用できなくなる。審査時に再度ログインできるよう、削除確認用と通常の機能確認用を分ける準備が必要。

## データ申告の照合案

Web版の解析とiPhoneアプリ内のデータ収集を混同しない。Appleの定義に沿って、アプリと組み込んだサービスが収集する情報を確認する。

| 確認するデータ | 実装上の用途 | 申告前の確認 |
| --- | --- | --- |
| 表示名・メールアドレス | 登録、ログイン、家族の識別 | 連絡先情報・ユーザーに関連付け・アプリの機能 |
| アカウントID・家族ID | 認証、家族単位のアクセス管理 | ユーザーID・ユーザーに関連付け・アプリの機能 |
| 商品・取引ID、契約状態、有効期限 | 購入・復元の検証、利用権限 | 購入履歴・ユーザーに関連付け・アプリの機能 |
| 献立・買い物・自作料理・チェック履歴 | ユーザーが登録し家族で共有する内容 | その他のユーザーコンテンツ等の区分を質問票と照合 |
| 写真・アレルギー・フィードバック | Web版側にも登録経路がある | iOSから実際に送信する範囲を確認し、Webの機能だけから決めない |
| 通信・エラーの記録 | Vercel、Supabase等の運用 | 保存範囲とユーザーへの関連付けを確認 |

今回確認したスマホ用コードにはGoogle Analytics等の広告追跡SDKは見つかっていない。トラッキングの回答は外部サービスを含む最終確認後に確定する。

参考：[AppleのAppプライバシー詳細](https://developer.apple.com/app-store/app-privacy-details/)。
