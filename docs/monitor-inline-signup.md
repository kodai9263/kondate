# モニター登録導線の改善（2026-09-16）

## 変更

- LPの3つのCTAから、ページ内の共通登録フォームへ移動する。
- ログイン済みなら二重登録させず、アプリへ案内する。
- 入力エラー、枠の確保失敗、登録失敗、確認メール待ちでモニター経由・UTM・招待を保持する。URLには名前・メールアドレス・パスワードを追加しない。
- 確認メール待ちでは登録フォームを非表示にし、受信トレイの確認を案内する。
- 既存の枠確保・失敗時の返却・認証処理を継続利用する。DB変更なし。

## 計測の定義

| イベント | 意味 |
| --- | --- |
| monitor_signup_click | LPの登録CTAクリック。変更後は登録ページへの遷移でなくページ内フォームへの移動 |
| monitor_signup_start | フォーム表示後、最初の入力変更（フォームのマウントごとに1回） |
| monitor_signup_submit | ブラウザの入力検証を通過して送信。登録成功ではない |
| monitor_app_click | ログイン済みの利用者がLPからアプリへ移動 |

開始・送信の付加情報は placement（monitor_inline / signup）のみ。入力内容は送らない。
GA4がブロックされている場合やタグ読み込み前はイベントを取得できない。登録完了は実データで別途照合し、送信数を登録数として扱わない。

- 型検査、変更ファイルのLint、ビルド、差分の空白検査を実施。
- ローカルPCブラウザで未ログインLPのCTAからフォームへの移動、未入力時の送信抑止、横はみ出しなし、確認メール待ち画面を確認。

## コミットメッセージ案

## プルリクエスト内容案

LPから登録開始までの画面遷移を省き、通常登録と共通のフォームを配置しました。失敗時や確認メール待ちでもモニター・招待・広告の文脈を保持し、入力開始と送信を登録完了とは区別して計測します。枠確保や認証の仕組み、課金、DBスキーマは変更していません。
