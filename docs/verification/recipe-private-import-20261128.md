# 家族用メニューのURL取り込み・作り方整理

実装ブランチ: `codex/recipe-url-facts`。基点: `49a9d82`。

## 変更内容

- Webとログイン済みモバイルの登録画面から、キッコーマンの対応レシピURLを読み取り、材料と作り方を確認・修正して家族内へ保存する。
- 材料のグループ名、元の分量、元の人数表記、出典URLを保持する。範囲人数は自動確定しない。写真・紹介文・栄養値は保存しない。
- 作り方の貼り付け後に改行を整理し、取り消しできる。順序・時間・温度を言い換えたり、要約したりしない。工程番号への参照がある文章は分割しない。
- 保存失敗時に入力を保持し、結果不明の再試行は同じID・内容で送る。
- サーバーとDBで対応URL・確認項目を検証する。既存の家族所有権・保留・版チェックを維持。読み取りは認証後、ユーザー単位で10秒に1回に制限する。
- 取得先はHTTPSの固定ホストとレシピパスだけ。転送先も検証し、12秒・2MB・3転送の上限を維持する。
- S&Bを含むその他のサイトの自動取得は追加していない。利用条件に沿った手入力・貼り付けは可能。

## 検証

- 関連ユニット/APIテスト9ファイル、合計62件成功。追加の出典確認テストを含む。
- `scripts/test-household-recipe-url-import-db.sh` 成功。全マイグレーションを隔離PostgreSQLに適用し、保存・再読込・出典保持・再送・献立保存・連続取得制限・別家族/匿名のアクセス拒否・既存保留を確認。
- 実際の指定URLの取得済みHTMLから、材料13項目、うちグループ付き4項目、工程4件、20分、人数は範囲のため未確定で読み取れることを確認。元ページ全文はリポジトリに含めない。
- Chromeのローカル確認用画面で、Web/iPhone用の実コンポーネントを操作。人数未入力の拒否、読み取り、整理/取り消し、読み取り失敗時の入力保持、テストDBへの保存と再取得を確認。
- 画面確認環境では認証とServer Actionの通信をテスト用アダプターに置換。材料は取得済みHTMLを使用。永続化は実際のローカルDBの保存RPC。実際の認証を通した本番E2Eではない。
- 変更箇所ESLint、Webアプリ本体の型チェック、モバイル全体の型チェック成功。
- モバイルViteビルド成功。検証専用URL `https://local-verification.invalid` を指定しており、生成物は配布用ではない。

## 残る確認

- 新規依存をインストールせず既存の依存を参照したため、ロックファイルと検証環境に差がある。Vitestは2.1.9、宣言は4.1.12。
- リポジトリ全体の型チェックは、既存の `tests/mobileInviteAcceptance.test.ts` でWeb/モバイルのSupabase型バージョン不一致があり未通過。今回のWebアプリ本体・モバイルは個別に通過。
- クリーンな依存環境でのCI/Next.js本番ビルド、iPhone実機、実認証での一連の動作は未確認。
- 本番マイグレーション、公開、App Store再提出は未実施。公開する場合はDBマイグレーションを先に適用し、Web/API、対応モバイルの順に反映して実認証で確認する。
- 注意書きと確認チェックは掲載許諾の取得・権利判断の代わりにならない。キッコーマンから私用取り込みについて個別の許諾が得られたと扱わない。S&Bは回答待ち。

## PR本文案

メニュー登録で、対応するキッコーマンのURLから材料・作り方を確認して家族内へ保存できるようにします。範囲人数の確認と材料グループ・出典の保持、貼り付けた作り方の改行整理、失敗時の入力保持をWebとモバイルに追加します。

認証・取得先/転送先の制限・回数制限・DBの所有権検証を適用しています。関連テスト62件、隔離DBの保存/権限テスト、ローカル画面の保存と再表示、アプリ本体の型チェック、モバイルビルドを確認。依存環境差による既存の全体型チェックエラー、実機/実認証E2E、本番反映は上記のとおり未確認です。
