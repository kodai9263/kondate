# スマホの取得・追加・起動改善

## 実装

- 認証・家族アクセス確認を通過したAPIリクエスト内だけで、ユーザー・家族・契約と設定を共有する。別リクエストやWebには共有しない。
- 品物追加は先に表示し、連続追加や既存品のチェック・削除を受け付ける。未確定の新しい行は保存完了までチェック・削除を無効にする。
- 追加の保存結果が不明な場合は再送せず、実状態を再取得する。
- オンライン起動も端末の保存済みリストを先に表示する。最新状態の確認までは閲覧のみ。
- 最新取得・保存から30秒以内の復帰で不要な取得を抑える。接続復旧時は再取得する。

## 検証

関連43テスト、型チェック、対象Lint、Web・スマホ・iOSビルド成功。ローカルの実App画面に通信遅延を入れ、応答前の追加表示、連続追加と削除、保存済みリストから最新リストへの切り替えを確認した。

実DBを使わず実APIコードを模擬クライアントで動かした呼び出し数（認証・DB・RPC合計）：

| 処理 | 改善前 | 改善後 |
| --- | ---: | ---: |
| 買い物GET | 28 | 17 |
| 今日GET | 20 | 15 |
| 手動チェックPATCH | 30 | 19 |
| 追加POST + GET | 56 | 34 |
| 削除POST + GET | 57 | 35 |
| 2か月の買い物GET | 37 | 23 |

回数の削減であり、実機・本番通信の待ち時間を実測した結果ではない。認証RPCは維持している。POST後のGETも維持している。

## PR本文案

スマホで品物追加と起動時の表示が通信完了まで待たされ、各API内で認証・家族設定の取得が重複していた。認可済みのリクエスト内で取得結果を共有し、追加を即時表示する保存キューに統合した。起動時は保存済みリストを閲覧用に先に表示し、短時間の復帰では再取得を抑える。

認証・家族の権限確認は維持。保存結果が不明な追加は再送せず実状態を確認する。関連43テスト、型・Lint、Web・スマホ・iOSビルドと遅延付きローカル画面を検証済み。実機・本番の時間計測は未実施。
