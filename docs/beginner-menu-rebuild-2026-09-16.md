## 変更内容

1. **全95品を6〜10工程に再構成。** 下ごしらえ、調味料を混ぜる作業、主菜と副菜、完成確認、盛り付けを順番に記載。朝に作業済みという前提をなくした。
2. **材料と工程の整合を修正。** 欠けていた中華丼・麻婆チャーハン・レバニラのスープを補完。主菜と副菜の材料、衣ととろみ、炒め油とたれを区別した。冷ややっこの副菜名を実際の「鶏ととうもろこしの炊き込みご飯」に統一した。
3. **加熱の判断を具体化。** 肉の厚さ、切る大きさ、火加減、加熱の目安、追加加熱の条件を記載。牡蠣ご飯は牡蠣を別鍋で加熱してから混ぜる。レバーは厚さ5mmと中心温度の確認を記載した。
4. **読める画面に変更。** 材料・調味料、必要な道具、番号付きの作り方を表示。計量や火加減の説明を開いて読める。家庭用の工程編集は折りたたみ、材料の分量は編集されないことを説明した。
5. **調理用の人数換算を追加。** 更新したレシピの基準を4人分に統一。材料を増減し、調味料も同じ比率で換算する。小数の野菜を分数で読みやすく表示する。温度・時間・切る大きさは換算しない。買い物用の単位切り上げは変更していない。
6. **完成までの時間を表示。** 下ごしらえ・待ち時間込みの目安は30〜110分。元の献立選択条件との互換性のため、既存の `cook_minutes` は維持し、`total_minutes` を別に保存・表示する。アレンジ済みの料理には、元の料理の新しい所要時間を表示しない。

## データ更新の範囲

- 家庭に属さない、94個の公式カタログIDと一致するレシピ。
- 共有品は、監査したID・公開区分・元URLの3条件を満たす「なすの豚しゃぶ香味だれ」だけ。
- 家庭ごとのアレンジ、自作レシピ、無関係な共有品は更新しない。アレンジ版は保存した材料を読み、その内容を新しい公式材料で置き換えない。
- 更新対象の当日以降のチェックを解除する。工程の意味が変わるため、以前のチェックを新しい作業の完了として扱わない。同一内容の再適用ではチェックを解除しない。
- 対象の古い朝工程・余分な末尾工程は削除され、関連するチェックもDBの既存仕様により削除される。残る工程の過去のチェックは保持するが、過去の画面もレシピ本文は新しい内容になる。完全な調理履歴の保存ではない。

### 再実行

```sh
npm test -- --exclude '**/.claude/**'
npm run typecheck
npm run lint -- --ignore-pattern '.claude/**'
npm run build
bash scripts/test-beginner-recipes-db.sh
```

DB検証はローカルPostgresと `tests/sql/authRealtimeFixture.sql` を使う。本番や既存DBへ接続しない。Auth/Realtimeの外部サービスは検証用の代替実装。

SQLの再生成は `node --import tsx scripts/generate-beginner-recipe-migration.ts`。確認用一覧はビルド後に `node --import tsx scripts/render-beginner-recipe-review.tsx` で生成する。

## 未検証・対象外

- **実際の調理、味、完成量、所要時間の実測、初心者による試作は未実施。** 文章とデータの整合を検証したもので、全料理の完成を実証したものではない。
- 本番DBへの適用、デプロイ後のログイン済み画面、保存・再読み込み・家族間同期は未実施。UIの確認はプレビューであり、本番の確認ではない。
- 朝食10種、旧固定ローテーション、今後URLから取り込む任意のレシピは今回の95品の改稿対象外。インポーターが任意の元サイトの材料と工程を意味までそろえる保証は追加していない。
- 既存の栄養概算値は再計算していない。細かな材料補完による差は残る。
- 同時に存在する家族招待などの別作業の変更は維持した。リリース時は今回の変更と混在させず、必要な変更を確認して反映する。
