# 登録なしの家族参加

招待された家族は、招待画面の「この家族グループに参加」を押すだけで参加する。メール・パスワードの入力は不要。登録済みでログイン中なら既存アカウントを使う。未ログインならSupabaseの匿名認証で端末のセッションを作る。

## データと権限

- 招待は7日間・1回限り。参加後の利用期間は招待期限とは別。
- 匿名ユーザーは有効な招待トークンを持つ場合だけ作成できる。`handle_new_user` が招待の消費とプロフィール作成を同じトランザクションで確定する。期限切れ・使用済み・解除済み・家族プラン終了なら作成を取り消す。
- 匿名参加でも既存の `profiles.household_id` とRLSを使う。参加先の献立・買い物・設定の共同編集権限は従来どおり。
- 匿名ユーザーは招待リンクの一覧取得・追加発行・共有解除・課金管理を行えない。
- 登録済みの招待者が自分の発行した招待を無効化できる。参加後なら対象者を空の個人グループへ移す。家族データやユーザーを削除しない。登録済み参加者の移動前のグループも削除しない。
- グループを移動したときは古い参加記録を無効化し、前の招待者が新しい所属を解除できないようにする。
- Realtimeは現在の参加者のIDを含む専用チャンネルへ配信する。共有解除後はそのユーザー宛に内容を送らず、既存接続からの受信も止める。新規購読はRLSで拒否する。
- 既に表示・取得された内容を相手端末から消去する機能ではない。解除後のDB読み書き・以後の通知を禁止する。
- 匿名参加では新規世帯やモニター枠を作らない。通常の登録処理は既存のまま。

## 端末の扱い

参加状態は同じブラウザで保持される。機種変更・ブラウザデータ削除・ログアウト後は再招待する。LINE内ブラウザで参加するとSafari/Chromeとは別セッションになるため、参加前に普段使うブラウザで開くよう案内する。端末を見分けたい場合は設定画面で表示名を変更できる。

## リリース手順

本番DBの変更・認証設定の変更・公開は、ユーザーの承認後に行う。

1. `202609120034_guest_family_invites.sql` をトランザクションで適用する。既存の関数・トリガー・RLSを更新するため、DBを先に反映する。
2. Supabase AuthのAnonymous Sign-Insを有効にする。プロジェクトでCAPTCHAを必須にしている場合は、この実装にチャレンジ入力を追加するか設定方針を決めてから有効化する。現在の画面はCAPTCHAトークンを送信しない。
3. アプリをデプロイする。Realtimeのチャンネル名が変わるため、古い画面を開いている利用者は再読み込みが必要。DB適用からデプロイまでの間は旧画面の自動同期が止まるが、保存APIは利用できる。
4. 別ブラウザで招待作成 → コピー → 匿名参加 → 献立・買い物の更新 → 再読み込み → 招待者による解除を確認する。解除した端末で旧グループの読み書きと更新受信ができないことも確認する。

## ローカル検証

```sh
npx vitest run --exclude '**/.claude/**'
npm run typecheck
bash scripts/test-family-invites-db.sh
```

DB検証は既存PostgreSQLのコマンドを使用し、独立した一時クラスタをUnixソケットだけで起動する。既存・本番DBには接続しない。全マイグレーションを適用して実際のRLS・RPC・トリガーを検証する。AuthとRealtimeの外部サービス部分はfixtureで置き換えるため、Supabase AuthのHTTP処理・本番のセッション保存・実際のWebSocket配信はリリース時の確認が別途必要。

公式仕様: [Supabase Anonymous Sign-Ins](https://supabase.com/docs/guides/auth/auth-anonymous)
